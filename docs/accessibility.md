# Accessibility

MapleMetrics targets **WCAG 2.2 level AA**. This page says what that means in practice, how it is
checked and what is not covered.

## What the interface does

- **Skip link and landmarks.** Every page starts with a "Skip to main content" link and has one
  `main` region, one `h1` and a labelled navigation.
- **Charts have text alternatives.** Each chart is an image with an accessible name and a
  description with the key numbers (start and end values and range for lines; highest, lowest and
  Canada for bars; latest value, forecast and range for forecasts). The same data is available as
  a table next to every chart.
- **Tables are real tables.** Each has a caption, column headers with `scope="col"` and row
  headers with `scope="row"`.
- **Keyboard.** Everything works without a mouse. Wide charts and tables scroll inside a
  focusable, labelled region, and focus is always visible (a 3 px outline).
- **No surprise page changes.** Choosing a province or indicator does nothing until you press
  Show, so arrowing through a list never reloads the page.
- **Colour.** Text meets 4.5:1 and chart colours meet 3:1 against their background, in both light
  and dark themes. Information is never carried by colour alone: lines are labelled at their ends
  and forecasts are dashed.
- **Language.** The page language is set on every page and follows the language switcher. French
  and English have the same content, including the chart descriptions.
- **Zoom and reflow.** Text resizes with the browser. At 320 CSS pixels wide the page does not
  scroll sideways, apart from the charts and tables, which scroll inside their own regions.

## How it is checked

| Check | Where | What it catches |
|---|---|---|
| Colour contrast tests | `apps/core/tests/test_accessibility.py` | A theme colour that drops below 4.5:1 (text) or 3:1 (chart) |
| Page structure tests | same file | Missing skip link, language, chart names, table captions, labels, focus on scroll regions, inline handlers |
| axe-core audit | `apps/core/tests/test_axe_audit.py`, CI job `accessibility` | Everything axe can detect, plus sideways scrolling at 320 px, on all pages, in English and French, light and dark |

The first two run with the normal test suite. The axe audit needs a browser, so it runs only when
the `AXE_JS` environment variable points at axe-core. To run it locally:

```bash
pip install playwright
playwright install chromium
npm install --no-save --prefix /tmp/axe axe-core@4.10.2
AXE_JS=/tmp/axe/node_modules/axe-core/axe.min.js pytest apps/core/tests/test_axe_audit.py --no-cov
```

## Known gaps

- **Automated tools find only part of the problems.** axe cannot judge things like whether a
  description is helpful or the reading order makes sense. This project has not yet been tested
  by people who use screen readers, voice control or switch devices. That testing is the next
  step.
- **Tooltips on chart points need a pointer.** The same numbers are in each chart's description and
  table, so nothing is lost, but the hover text itself is not keyboard-reachable.
- **Swagger UI.** The interactive API documentation at `/api/v1/docs/` is generated by a third
  party library and has not been audited here. The API itself is plain JSON, and the OpenAPI
  schema is at `/api/v1/schema/`.

## Reporting a problem

Open an issue on the project's GitHub page and say which page, which browser and which assistive
technology you used. Accessibility problems are treated as bugs.
