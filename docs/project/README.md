# Project management

MapleMetrics was run as a small, time-boxed project with a plan, a risk register and a decision
log, not only as code. These documents are the record. They are written from the repository's own
history (25 commits, one release tag) and say plainly what is finished and what is not.

| Document | What it answers |
|---|---|
| [Charter](charter.md) | Why the project exists, what is in and out of scope, how success is measured and how it was run |
| [Roadmap and backlog](backlog.md) | What was delivered in each sprint, and what is planned next, in priority order |
| [Sprint reviews](sprint-reviews.md) | For each sprint: the goal, the evidence, what went well, what went wrong and what changed |
| [Risk register](risk-register.md) | What could go wrong, how likely and how bad, and what is done about it |
| [Decision log](decision-log.md) | The choices that shaped the design, the alternatives and the trade-offs |
| [Case study](case-study.md) | A one-page summary of the project and what it demonstrates |

How these documents are kept up to date: the backlog and risk register are reviewed at the end of
every sprint, and every decision that is hard to reverse gets an entry in the decision log
before the work is merged. The [changelog](../../CHANGELOG.md) is the release record.
